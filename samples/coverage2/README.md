# Second coverage form: what the first export could not show

`ctosim_coverage2.xlsx` settles the export conventions that spec 08 lists
under "Not observed in the real exports", and the cases the three
submissions of the first coverage form left empty:

| What | Where in the form | Question for the export |
|---|---|---|
| Geopoint in a repeat | `member_gps` (in `member`), `plot_gps` (in `plot`) | `member_gps-Latitude_1` or `member_gps_1-Latitude`? |
| select_multiple in a nested repeat | `job_days` (in `member` > `job`) | order of the choice and the two instance numbers (`job_days_6_1_2`?) |
| Counted repeat inside a repeat | `child`, counted by `n_children` | name of its count column (`child_count_1`?) |
| `instanceName` | settings `instance_name` | name and position of the column |
| Choice values with letters and hyphens | `transport` (`bus`, `moto-taxi`, `x2`) | `transport_moto_taxi` or `transport_moto-taxi`? |
| Relevant select_multiple left blank | `member_activities` | are its dummy cells empty or 0? |
| Audit and comment fields | `audio_audit` (Collect only), `sv_count`, `sv_list`, `field_comments` | what they hold: audio file URL, number, comma-separated field list, comments file URL (and its name) |
| Enumerator-controlled top-level repeat with instances | `plot` | wide columns and the long `plot` file |
| Refused consent | `consent` = No | cells of the whole skipped group |

Both files are generated by `build_coverage2_form.py`; edit the script, not
the workbook. All names and values are fictitious.

## What to do in SurveyCTO

1. **Deploy** on the test server: *Design → Upload form definition*, file
   `ctosim_coverage2.xlsx`, with `hh_preload.csv` attached.
2. **Fill 3 test submissions** with invented answers only. If you can, fill
   submission **B with SurveyCTO Collect on an Android device**: the audio
   audit only works there (web browsers cannot record audio in the
   background). Speed violations and comments work on the web too.
   - **Speed violations** (B and C): `resp_name` and `hh_size` must stay on
     screen 10 seconds; answer them at once and try to move on immediately,
     two or three times, before waiting.
   - **Comments** (B and C): add a short comment on one or two questions
     (web form: *Options* menu, *Add comment*; Collect: three-dot menu or
     the pencil button).
   - **A:** consent = **No** (the interview stops).
   - **B:** consent = Yes; assets **Radio** and **Bicycle**; transport
     **Bus** and **Motorbike taxi**; household size **2**.
     - Member 1: capture the location; activities **Farming**; children
       **2** (any names); add **2 jobs**: job 1 days **Monday** and
       **Saturday**, job 2 days **Don't know**.
     - Member 2: **skip** the location; leave activities **blank**;
       children **0**; **no job**.
     - Add **2 plots**, the first with a location, the second without.
   - **C:** consent = Yes; assets **Don't know** only; transport **Other
     (code with a digit)** only; household size **1**; member 1 with a
     location, activities **None**, **1 child**, **1 job** with days
     **Saturday**; **1 plot** with a location.
3. **Export** without changing the default options, keeping the files
   exactly as downloaded: the **wide** CSV, the **long** CSVs (main file
   plus one per repeat), the Stata `.do` templates if generated, and, if
   possible, the attachments of submission B (text audit, audio audit,
   comments).
4. Put the files in `samples/coverage2/wide/` and `samples/coverage2/long/`
   (attachments in `samples/coverage2/media/`), as for the first form, and
   note which device each submission was filled on.

As for the first form, the submitter's e-mail and the server name will be
anonymised before the exports are committed as test fixtures.
