# Coverage form: getting a real SurveyCTO export without real data

`ctosim_coverage.xlsx` is a small SurveyCTO form that uses every field type
and structure the exporter (spec 08) must reproduce: SurveyCTO metadata,
groups, a counted repeat with a nested enumerator-controlled repeat, a
top-level enumerator-controlled repeat, `select_multiple` with negative
codes, a cascading select, geopoint, date / time / datetime, an image,
comments, a text audit, `calculate_here` and a `pulldata()` preload from
`hh_preload.csv`. All names and values are fictitious.

Both files are generated by `build_coverage_form.py`; edit the script, not
the workbook.

## What to do in SurveyCTO

1. **Deploy** on a test server (or a test project): *Design → Upload form
   definition*, file `ctosim_coverage.xlsx`, with `hh_preload.csv` as an
   attached file.
2. **Fill 3 test submissions** with the web form (about two minutes each),
   using invented answers only:
   - submission A: consent = **No** (the interview stops early);
   - submission B: consent = Yes, household size **3**; give the first
     member **2 jobs**, the second **none**, the third **1**; add **2
     plots**; in *Assets* tick several items including **Other**;
   - submission C: consent = Yes, household size **1**, no job, **1 plot**;
     in *Assets* tick **Don't know** only; skip the photo and the location.
3. **Export the data**, without changing SurveyCTO's default options, and
   keep the exported files exactly as downloaded:
   - the **wide** CSV (one row per submission);
   - the **long** format (the main CSV plus one CSV per repeat group);
   - if your team uses it, the Stata files SurveyCTO generates (the `.do`
     import template);
   - the attachments of one submission (the text audit and comments CSV
     files), only to see how they are named and referenced.
4. Put the files in `samples/coverage/exports/` (or send them), and note
   which export options were on (for example "select_multiple dummy
   columns", date format).

These exports contain no personal data, so they can be committed as
reference fixtures for the exporter's tests.
