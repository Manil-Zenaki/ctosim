# Third coverage form: every SurveyCTO feature not yet checked

`ctosim_coverage3.xlsx` (and `ctosim_coverage3_v2.xlsx`, the same form
with one question added) covers the SurveyCTO features and cases that no
real export has shown yet. It was built from an inventory of SurveyCTO's
documentation (field types, appearances, functions, settings) compared
with what the first two coverage forms and the test suite already cover.
Files are generated by `build_coverage3_form.py`; edit the script, not
the workbooks. `villages.csv` must be attached to the form (it feeds the
`search()` question). All values are fictitious.

## 1. Inventory

Status: **E** = seen in a real export (coverage 1 or 2); **U** = covered by
unit tests only (never compared with SurveyCTO); **–** = not covered
before this form. "Where" names the coverage-3 field.

### Functions (computed with no input, in the `oracle` group)

The export gives SurveyCTO's own result for each one, to compare with the
simulator's. Numbers: `div`, `mod`, `round`, `int`, `pow`, `sqrt`, `exp`,
`log10`, `pi`, `abs`, `min`/`max` of values, `format-number`, division by
zero, `number('abc')`, 0.1 + 0.2, large products, `string(5.0)`.
Logic: comparisons stored as values, `if`, `coalesce`, `empty`,
`relevant`. Text: `concat`, `substr`, `string-length`, `lower`, `upper`,
`linebreak`, commas and quotes, `regex`, `hash`. Dates: `today()`,
`now()`, `format-date-time` (day and month names), date arithmetic,
`date(number)`, `decimal-date-time`, `decimal-time`, `version()`. Lists
and selects: `selected`, `count-selected`, `selected-at`, `choice-label`,
`count-items`, `item-at`, `item-index`, `item-present`, `de-duplicate`,
`rank-value`. Random: `once(uuid())`, `once(random())`. Repeats (`auto`,
3 computed rows): `count`, `sum`, `min`, `max`, `join`,
**`count-if`, `sum-if`, `join-if`, `min-if`, `max-if`, `rank-index-if`**,
`indexed-repeat`, `rank-index`.

## 2. What running this form through ctosim already shows

Before any real export, the simulator was run on this form. To fix:

1. **`count-if`, `sum-if`, `join-if`, `min-if`, `max-if`,
   `rank-index-if` make the walk fail** ("This field is repeated"). They
   are stubs (spec 03) whose condition is evaluated on a whole repeat.
   Any form using them cannot be simulated today.
2. **`format-date-time` depends on the machine's language**: `%a %b`
   gives `lun. janv.` on a French Windows, so outputs differ between
   machines.
3. **A counted repeat with a count of 0 gets one instance** in the
   simulator.
4. **`search()` questions offer the placeholder row** (`village_id`)
   instead of the rows of the CSV file.
5. **`decimal-time()` of a text value fails** in the engine (the form
   uses a time field instead, to stay loadable).

To check against the export (the simulator's current output in brackets):
`today()` and dates as calculate results (`2026-01-27T00:00:00.000Z`),
booleans (`1` / `0`), `number('abc')` (empty), `1 div 0` (`Infinity`),
0.1 + 0.2 (`0.30000000000000004`), `month-year` dates (any day),
`instanceName` ending with a space (kept), a calculated default the
enumerator tries to change.

## 3. Not covered here (needs server configuration)

Ask if you want any of these tested; each needs a setting on the server
or in the form that this form cannot carry alone:

- **enumerator** field type and `enumerator-name()` / `enumerator-id()`
  (needs an enumerator dataset);
- **case management** (`caseid` filled from a cases dataset);
- **review and corrections workflow** (`review_*` columns in exports);
- **encryption** (`public_key` setting: encrypted fields in exports);
- **server datasets** published from a form, `pulldata()` from a dataset
  instead of a CSV;
- **field plug-ins**, **phone-call** functions, **speed violations
  audit** (syntax not documented);
- **translations** (no effect on exports; the converter already handles
  them).

## 4. What to do in SurveyCTO

1. **Deploy** `ctosim_coverage3.xlsx` with **`villages.csv` attached**.
2. **Fill three submissions**, following each label's instructions. The
   first question asks for the submission code (A, B or C).
   - **A: SurveyCTO Collect on Android**, everything:
     - record the audio and video, attach a file, sign, scan any barcode,
       and record the line and the shape outdoors (or anywhere with GPS);
     - on `resp_code` and on `i_minimum_time`, try to move on at once
       (to get speed violations);
     - change `def_change` to xyz, and try to change `calc_default` to 99;
     - leave `m_blank` blank;
     - add a comment on one or two questions.
   - **B: web form**, same answers where the web allows them; skip what
     it cannot do (video, barcode, sensors); add a comment.
   - **C: SurveyCTO Collect on Android**, minimal:
     - on the two questions with a minimum time, **wait 10 seconds**
       before moving on (no speed violation);
     - set **`n_people` to 0**;
     - no comment, no media.
3. **Optional, form versions:** after A, B and C, upload
   `ctosim_coverage3_v2.xlsx` as a new version of the same form (same
   form id, with `villages.csv`), and fill **one more submission D**
   (web is fine): type D as the submission code (only version 2 accepts
   it) and v2 in the new question.
4. **Export** without changing the default options: the wide CSV, the
   long CSVs, the Stata templates, and if possible the attachments of
   submission A (text audit, comments, audio). Put them in
   `samples/coverage3/wide/`, `samples/coverage3/long/` and
   `samples/coverage3/media/`. The export report PDF is not needed.
5. Note anything that did not behave as the labels said (a question that
   would not accept the value, an error on upload, a skipped step).

As before, the e-mail, the server name and device ids will be anonymised
before the exports are committed.

## Exports received (2026-10-11)

`wide/` and `long/` hold the exports of the four submissions, with the
Stata templates SurveyCTO generated: A and C filled with SurveyCTO
Collect on Android, B and D on the web; A, B and C under version
2610120001, D under version 2610120003 (`ctosim_coverage3_v2.xlsx`).
`media/` holds the CSV attachments (text audits of all four submissions,
comments of A and B); the recordings, video and images of A are kept
locally and not committed.

Edits to the downloaded files: the submitter's e-mail is replaced by
`enumerator@example.org`, the server name in URLs by `example`, the
device's Android ID by `a1b2c3d4e5f60718`, the phone number by
`15555550100`, and the coordinates of
`g_trace` are moved to a fictitious place (the digits after the third
decimal, the altitude and the accuracy are kept). The export report PDF
is not committed.

Departures from the scenarios:

- the first version only accepted A, B or C as the submission code;
  version 2 was corrected to accept D before submission D was filled;
- Collect needed a separate barcode app (SurveyCTO names QR & Barcode
  Reader) before `m_barcode` could be scanned;
- `g_shape` is empty (no shape could be walked indoors);
- submission C still has a speed violation on `resp_code`.
